# Astryx UI migration

**Superseded:** The Neutral visual change was rejected. The current implementation follows [Preserve LoopMart design](2026-11-13-astryx-preserve-design.md), restoring the original public blue and confirmed gray-green admin themes. Verification below records the earlier migration only.

**Goal:** Use Astryx components and its Neutral theme throughout the public Web and admin interfaces, preserving current functionality.

**Architecture:** Both Next.js apps share one theme provider and the same component library. Existing presentation components migrate in place; API, authentication, navigation, permissions and database behavior stay intact. No custom visual CSS or parallel design tokens remain.

## Work

- [x] Install matching Astryx Core, CLI and Neutral theme; initialize project guidance and connect the shared provider.
- [x] Replace public navigation, browse/detail cards, publishing, school picker, chat, profile and media presentation with Astryx components.
- [x] Replace admin navigation, resource tables/details and audit confirmation with Astryx components.
- [x] Migrate shared forms, authentication, account, settings, contact, privacy, feedback and remaining inline presentation; remove obsolete styles.
- [x] Verify component coverage, input validation, localization and responsive layouts. Run unit tests, type checks, production builds, Astryx doctor and browser interaction checks.

## Acceptance

- Both apps import the same provider and use the production Astryx CSS and theme.
- All user-visible controls, text and layout use Astryx components; exceptional native content elements are semantic only.
- Tokens or component props determine colors, typography, spacing, radii and control states.
- Forms retain exact money conversion, seat limits, timezone handling, drafts and submit locking.
- Confirmation dialogs retain reason validation, cancellation, focus and retry behavior.
- No horizontal page overflow at mobile widths; table overflow stays inside its scroll region.
- Browser checks exercise both locales, public/admin routes, forms, dialogs and navigation without changing production data.

## Verification

- `npm test`: 37 passing, including the new AST design-system gate and integer-seat validation.
- `npm run typecheck`: root and both Next.js apps pass.
- `npm run build`: server and both production apps build, with standalone assets prepared.
- Astryx doctor on both builds: zero failures. Its external-font warning was checked in the browser: Figtree loads and is used by headings.
- `tests/browser/astryx_ui.py --case web` and `--case admin`: both exit 0. The suite covers 14 public and 17 admin routes in Chinese/English at 1440, 390 and 320 widths; modal mobile navigation also runs at both mobile widths in both locales.
- Interaction coverage includes required fields, exact currency/seat payloads, browser-independent Chicago departure conversion, invalid-date submission protection, free-text/preset locations, school selection/focus, 45-message chat scrolling, and admin confirmation focus/cancel/failure/retry.
- Browser traffic uses isolated in-memory API/auth fixtures, with no database writes. Existing real-API suites were adapted and syntax-checked; their controls were exercised with these fixtures, and the full database suites were not run for this UI migration.
- Screenshots are retained in the ignored `.superpowers/e2e/astryx/` directory.
