# LoopMart 完整 UI 设计说明

日期：2026-11-13
状态：依据已认可的交互原型整理；本次交付为设计说明与实施计划。
适用：Web 用户端、Admin 管理端及其移动浏览器布局；原生 iOS 不在本轮实现范围。

## 1. 设计依据与优先级

本说明承接 `2026-11-12-loopmart-design.md` 的业务、认证、权限与基础设施约束，仅更新界面和操作方式。已经实现的业务能力必须保留。发生冲突时，业务安全约束优先；视觉上以本次最终确认的左右布局为准。

用户已确认：

1. 用户端采用现代网页版购物平台结构，管理端采用独立后台工作台；不照搬 BM。
2. 商品保留图片展示的设计。
3. 完善拼车、发布、消息及移动端交互。
4. **桌面拼车列表和商品一致：左侧筛选、右侧卡片网格；拼车详情为左侧行程信息、右侧费用和联系操作。** 早期上下结构的拼车原型已废弃。

最终交互参考：本地原型 `.superpowers/brainstorm/30582-1794536106/content/marketplace-rides-left-right-v2.html`。该目录被 Git 忽略；本文为长期实现依据，不能依赖临时原型服务器。原型中的照片、样例用户、样例消息、演示导航和控件不作为生产数据或完整功能授权。

## 2. 范围与保留边界

| 本轮覆盖 | 保持现有约束 | 不纳入本轮 |
|---|---|---|
| Web/Admin 整体视觉、导航、页面与状态 | 自有 PostgreSQL、独立 Better Auth | 支付、订单、结算、预订 |
| 商品和拼车浏览、详情、发布、编辑 | 单一 Purdue 社区、服务端权限 | 多社区选择、原生 iOS 开发 |
| 收藏、用户资料、聊天、举报、联系 | 商品收藏；聊天按用户对合并 | 拼车收藏、群聊、图片消息 |
| 后台全部已有模块 | 管理写入原因、二次确认、事务审计 | 批量管理动作、新权限模型 |
| 图片组件与未来媒体数据接入边界 | 当前无真实上传与存储适配器 | AWS/Supabase/对象存储接入、视频播放 |
| 有效的商品筛选 | 现有不透明游标及稳定排序 | 伪造页码、全库客户端过滤 |

不升级主要依赖、不迁移数据库、不修改生产配置和 OCI；Cardmaster 不受影响。真实图片数据尚不可用，不以占位照片伪装真实商品。

## 3. 信息架构与导航

### 3.1 Web

桌面顶栏：品牌链接、商品全局搜索、收藏、消息（未读数）、账号菜单、主按钮“发布”。次导航：市场、拼车、我的发布；Purdue 为当前社区上下文，不提供切换入口。隐私、联系、语言切换放账号菜单或页脚，不占用主操作空间。

| 页面 | 规范地址 | 关键行为 |
|---|---|---|
| 市场 | `/items`，根地址 `/` 指向市场 | 搜索与筛选进入 URL |
| 商品详情 | `/items/:id` | 可直达、刷新、分享、返回原列表 |
| 拼车与详情 | `/rides`、`/rides/:id` | 与商品保持相同左右结构 |
| 发布与编辑 | `/publish?kind=items` 或 `rides`；`/items/:id/edit`、`/rides/:id/edit` | 编辑不覆盖发布草稿 |
| 收藏 | `/favorites` | 仅商品 |
| 消息 | `/messages`、`/messages/:id` | 桌面双栏，手机分屏导航 |
| 个人与发布 | `/account`、`/account/listings?kind=items` 或 `rides` | 账号设置与自己的内容分区 |
| 公开资料 | `/profiles/:id` | 不暴露邮箱和内部字段 |
| 登录及辅助页面 | `/login`、`/privacy`、`/contact` | 保留已有认证全部流程 |

使用真实链接与浏览器历史。保留旧 `/#items`、`/#rides`、`/#conversations`、`/#profile` 等书签转换，旧详情路径继续可访问。认证回调带 token 的 URL 优先处理，不能被规范化丢失。查询、筛选、排序变化清空旧游标；详情返回恢复列表条件、已加载批次和滚动位置。URL 中不放密码、邮件令牌副本或用户聊天正文。

### 3.2 Admin

管理端独立应用和导航，不与用户端混合。规范地址在管理端使用 `/admin/...`：overview、users、items、rides、conversations、reports、community-messages、contact、settings、audit。详情追加 `/:id`。保留现有无 `/admin` 前缀及 auth-settings、community-admin、privacy-policy、contact-form 的入口映射。

|---|---|
| 品牌/主操作 | `#2659ec`；hover `#1e47c0` |
| 页面/面板 | `#f5f7fb` / `#ffffff` |
| 正文/次级文字 | `#17243b` / `#53627a` |
| 分隔/选中背景 | `#e2e7ef` / `#edf2ff` |

| 字体 | 系统中文/拉丁字体；正文 14–16px、次级 12–14px、页标题 28px |

使用细边框和轻阴影，不堆叠大渐变、装饰横幅、slogan 或解释性副标题。品牌规范是内部开发依据，不写成产品文案。具体前景/背景组合须验证 WCAG AA 对比度，不能因指定色值豁免。

### 4.2 响应式

| 宽度 | 用户端 | 管理端 |
|---|---|---|
| ≥1200px | 内容最大 1440px；左右留白 32px；筛选 232px + 间距24px + 三列卡片 | 224px 固定侧栏；表格+详情抽屉 |
| 768–1199px | 页边距24px；列表两列；筛选收进弹层；详情两栏，窄处单栏 | 折叠侧栏，优先列+局部表格滚动 |
| <768px | 页边距16px；商品两列；拼车一列；详情单栏；筛选底部面板 | 菜单抽屉；记录卡片/关键列；详情全宽 |

桌面详情左列 `minmax(0, 1fr)`、右列约360px；发布右摘要约320px。手机详情底部固定联系操作，发布底部固定草稿/发布操作，内容增加等高底部留白。处理 `env(safe-area-inset-bottom)`、`100dvh`、长英文、浏览器缩放与软键盘。320px 不产生整页横向溢出。

## 5. 市场列表

左侧分类与价格、成色、交付方式筛选；右侧标题、结果状态、排序与商品网格。搜索框按提交触发；分类/枚举选择立即应用，价格用“应用”提交，移动筛选在面板内暂存，点击“应用”后整体生效。清空恢复默认。加载中保留旧内容并明确加载状态，避免把暂时空列表显示为“无结果”。

价格支持最低/最高 USD，使用字符串精确转整数美分；包含边界，0合法，负值、超过两位小数、最小大于最大均阻止查询并定位错误。成色与交付方式使用既有枚举。需要 API 的增量只读筛选：`minPriceCents`、`maxPriceCents`、`condition`、`deliveryMethod`；不需要 schema 变更。由服务端在分页前筛选，不能仅筛选已加载页面。

排序本轮只提供“最新发布”，不展示未支持的价格排序。使用“加载更多”延续不透明游标；没有真实总数时不显示虚构总量或1/2/3页码。追加失败保留已加载内容并可重试；条件改变后忽略旧请求迟到结果。

卡片：4:3 媒体区、两行内标题、USD价格、成色/交付方式、发布者和发布时间、独立收藏按钮。整卡主要区域为详情链接；收藏按钮不得嵌套在链接中。无图片展示统一中性占位，不强行占满过高空间。自己的商品显示管理入口；收藏变化以成功响应为准，失败保留原状态。

## 6. 商品详情与媒体

左：主图、缩略图、描述。右：标题、价格、成色/交付方式、联系卖家、收藏、发布者资料、举报。移动按主图→核心信息→操作→描述顺序排列。详情不使用通用 JSON 渲染器，不显示数据库 ID、publisherId、原始状态码或私密邮箱。

有多图时缩略图切换；主图打开可关闭的查看器，Esc关闭、焦点返回原主图，支持键盘切换。有一图不制造多图控件；无图或图加载失败显示降级状态。图片区保留宽高比防止布局跳动；非首屏图片懒加载；alt来自内容语义，不重复全部正文。

**媒体边界：** 现有 `packages/integrations/src/media.ts` 的对象ID、可见性与查看者解析契约继续保留。UI接收由受信适配器提供的展示数据 `{id,url,alt}`，不直接把任意用户 URL 视为可信媒体。当前 API 不提供图片，因此默认空数组。测试/独立 demo 可注入样图，生产列表不注入示例图片。

当前发布页隐藏文件选择、上传、封面排序和视频入口。原型中的本地选图只说明未来布局，不能交付“选择成功但发布后丢图”的实现。以后接入存储时单独实现权限校验、上传进度/失败重试、资源关联、清理和可见性；本轮不增加上传接口、存储表或生产允许域配置。

“联系卖家”创建/打开已有用户对会话，带商品引用；本人不显示联系自己。不可访问/下架详情给出明确状态和返回入口，不能继续假装发布成功或可联系。

## 7. 拼车列表与详情

**桌面列表：左侧筛选栏，右侧卡片网格。** 筛选为出发地、目的地、出发日期；右侧提供出发时间升/降序。筛选栏与市场共享宽度和间距，不能恢复成顶部一排筛选加全宽纵向路线列表。

卡片展示出发地→目的地、日期/时间、明确时区、每人费用、剩余座位、发布者。备注只展示摘要；没有备注不添加解释文案。不提供拼车收藏、预订、扣座或付款。

**桌面详情：左侧行程信息，右侧费用、司机与“联系车主”。** 左侧包含路线、出发日期/时间/时区、总座位与余座、费用说明、备注；右侧联系行为复用商品的用户对会话与引用流程。手机单列，费用与联系操作便于触达。

出发地/目的地推荐 Purdue、Indianapolis、IND、Chicago、ORD、MDW、UIUC，允许自定义。输入控件采用既有地点选项的实际字符串。时区默认既有值，常用选项 America/Indiana/Indianapolis、America/Chicago；编辑时保留合法的其他已有时区。

所有日期展示/筛选按行程存储的 IANA 时区解释。不能用浏览器所在时区替代；发布将墙上时间与所选时区组合转换 UTC。夏令时不存在的时间拒绝；重复时间使用现有转换策略并在提交前显式确认实际偏移。无到达时间、里程、地图或估算行程时长。

## 8. 发布、编辑与草稿

统一“发布”入口，商品/拼车切换。桌面左侧分组表单、右侧摘要与主操作；手机单列表单+固定底部操作。

| 商品表单 | 拼车表单 |
|---|---|
| 标题、描述、分类、成色 | 出发地、目的地、日期/时间、时区 |
| USD价格、交付方式 | USD每人费用、费用说明 |
| 不显示未启用的图片上传 | 总座位、剩余座位、备注 |

直接复用 `money.ts` 和 `time.ts` 的精确转换及测试。禁止浮点乘100。金额可为0；余座在0和总座位之间；服务端校验始终是最终依据。

主按钮具体为“发布商品”“发布拼车”“保存修改”；不能各处都叫“保存”。提交中禁用重复提交，失败保留输入、焦点定位到首个无效字段，服务端通用错误出现在表单顶部。成功跳转对应详情并更新自己的列表。

草稿按现有 `loopmart-draft-${ownerId}-${kind}` 隔离，只有商品/拼车各一份。保留自动保存以及恢复/丢弃；固定操作“保存草稿”触发立即保存与短状态反馈。未登录不写入其他人的草稿；切账号不带出原账号内容。编辑已有内容不覆盖发布草稿；成功只删除本账号本类型的发布草稿。切换类型保留两份数据；存储不可用时仍可填写与提交，报告草稿保存失败。

## 9. 消息与会话

桌面左列约300px：会话搜索、最近消息、时间、未读数；右列当前聊天。按对方名字/最近消息过滤当前会话集合；需要获取全部分页后才可声称搜索全部会话。当前API返回集合时沿用集合语义，不增加无依据的全历史消息搜索。

聊天顶部：对方姓名、资料入口、举报菜单。正文：按顺序的文本消息、时间和真实已读信息、可点击的商品/拼车引用卡。引用失效保留可用摘要并禁用失效跳转；不展示未经API支持的在线状态/输入中状态。

底部为多行输入框和“发送”；Enter发送，Shift+Enter换行，中文输入法组合期间不发送。空白消息不能发送；失败保留正文且重试复用原clientId，不能制造重复消息。发送成功清空当前输入；切会话不将输入发给另一个人。

保留现有 SSE 与断线查询补齐、不透明消息游标、已读游标和用户对合并逻辑。打开当前可见会话后才标记已读；隐藏标签页/未选会话的新消息只更新未读。用户阅读旧消息时不强制滚至底部，以“新消息”入口提示；自己发送或已在底部才滚动。

手机：会话列表与聊天独立页面；返回恢复列表滚动与搜索。聊天隐藏全局底部导航，输入框在键盘上方；发送失败/断线提示简短可操作。无媒体消息与附件上传。

## 10. 账号、收藏与辅助页面

登录、注册、验证邮箱、重发验证、忘记/重置密码、改邮箱、改密码、改姓名、退出均保留现有 Better Auth 调用和状态。SMTP未配置时必须显示服务返回的失败，不伪造邮件已发送；不实现生产验证绕过。

我的发布支持商品/拼车切换、已有状态筛选、编辑、下架/删除；高影响操作明确确认。用户不能恢复违规下架内容。收藏页复用商品卡片，失效内容不能误导为仍在出售。公开资料仅显示服务端允许的名称/验证信息和发布内容；不要从邮箱域名推断验证徽标。

举报保留商品/拼车/用户/会话四类，使用原因选择、补充说明和提交结果。联系页面服从public/settings的开关；隐私按当前语言显示。空状态只提供清晰状态与主要操作，不添加理念和教学段落。

## 11. Admin 工作台

侧栏按运营任务排列：总览、用户、商品、拼车、会话、举报、社区消息、联系、设置、审计。桌面顶部面包屑、页标题、有效筛选、列表；明细在带地址的抽屉或全宽面板，刷新仍可打开。跨模块共用控件，不共用用户端顶栏。

| 模块 | 默认主要内容与操作 |
|---|---|
| 总览 | 使用真实 API 计数；不制造趋势图或不存在的交易额 |
| 用户 | 名称/邮箱/角色/封禁；创建、修改角色、封禁、设密码、发重置邮件 |
| 商品 | 标题/价格/状态/发布者/日期；查看、代建、编辑、删除；图片列按数据能力显示 |
| 拼车 | 路线/出发时区时间/余座/费用/状态；查看、代建、编辑、删除 |
| 会话 | 参与者/最近消息/时间；只读查看消息，遵循管理权限 |
| 举报 | 目标类型/原因/状态/时间；查看目标，reviewed/dismissed/violation_confirmed |
| 社区消息 | 配置的官方发送身份、收件人搜索、正文、原因和发送确认 |
| 联系 | 邮箱/主题/时间/状态；查看正文、处理备注、open/resolved |
| 设置 | 认证邮箱规则、官方身份、联系开关、中英文隐私分组表单 |
| 审计 | 操作人/动作/目标/时间；结构化 before/after 只读比较 |

保留既有管理筛选（见API契约），不在表格中摆设无效控件。不放批量选择框，不暗示已支持批量操作。敏感操作使用界面内确认弹窗：目标、改动摘要、必填原因、确认按钮；避免系统prompt。密码不回显、不进入可读摘要或审计展示。

角色/封禁由服务端最终判定，前端隐藏入口不是授权。401转登录并保留安全返回路径；403显示权限状态。失败不能显示成功或修改本地列表假装已持久化。手机可用菜单抽屉与记录卡，仍保留完整操作和原因/确认流程。

## 12. 组件、状态与可访问性

共用：Button、Field、Dialog、Sheet、Tabs、Badge、Skeleton、EmptyState、ErrorState、LoadMore、MediaGallery。Web：WebShell、FilterSidebar、ItemCard、RideCard、PublishForm、ConversationList/ChatPanel。Admin：AdminShell、ResourceTable、RecordDrawer、ConfirmAction。实际代码按已有技术栈实现，不引入大型UI库。

| 状态 | 规则 |
|---|---|
| 初次加载 | 对应布局骨架，区域aria-busy；不清空全局导航 |
| 过滤/刷新 | 保留现有内容，旧响应不能覆盖新条件 |
| 空集合 | 简短“暂无内容”与适合的发布/返回操作 |
| 无匹配结果 | “没有匹配结果”与清空筛选 |
| 网络/服务异常 | 安全文案与重试；无堆栈/SQL/凭据 |
| 401/未验证/封禁/403 | 按真实身份状态展示可行动入口，不混为网络失败 |
| 删除/下架/不存在 | 不可用状态与返回，引用降级 |
| 写入中/成功/失败 | 禁止重复请求、局部状态反馈、失败保留输入 |

中文/英文覆盖导航、枚举、表单、错误、确认和空状态。使用语义化链接/按钮、关联label、aria-current/pressed、可见焦点；焦点环不能删除。Dialog/Sheet有标题、焦点约束、Esc和返回焦点，背景不可操作。降低动态效果偏好生效；禁止仅靠颜色区分状态。

## 13. 技术落点与验收标准

基于现有 Next.js、React、共享UI与API，不重写服务层。将 `Client.tsx` 的导航/页面渲染按Web与Admin逐步提取，继续复用 `api.ts`、`money.ts`、`time.ts`、`errors.ts`、Better Auth 与服务端鉴权。用实际pathname导航和现有catchall承接直达地址，避免另建路由框架。

验收必须同时满足：

- 桌面市场和拼车都为左筛选+右网格；两种详情都为左内容+右操作。
- 1440、1024、768、390、320px布局无整页横向溢出；手机消息输入和固定操作不遮挡内容。
- 图片：多图、单图、无图、失效图均可用；首版没有真实上传入口或生产样图注入。
- 筛选真实参与分页前查询；游标追加无漏项/重复；返回恢复列表；没有假页码。
- 商品/拼车发布编辑、草稿隔离、精确金额、时区、收藏、四类举报、联系和账号流程可完成。
- 两用户跨商品/拼车引用仍是一条会话，断线补齐、未读/已读、失败重试无重复。
- Admin所有既有模块和筛选可用；管理写入原因、确认、服务端审计不退化。
- 中英文、键盘、输入法、焦点和失败状态通过浏览器检查；无控制台未处理异常。
- 现有单元/数据库集成测试、Web/Admin类型检查和生产构建通过。浏览器断言随真实界面语义更新，不删除业务断言以掩盖回归。

实施拆分、文件责任和验证命令见配套实施计划。本说明不是已完成UI实现的声明。
